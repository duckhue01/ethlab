📊 Subtree Weights

LMD-GHOST Pseudocode

def get_head(store):
    # Start from the justified checkpoint
    head = store.justified_checkpoint.root

    while True:
        children = get_children(head)
        if len(children) == 0:
            return head  # leaf = head

        # For each child, sum weights
        # of validators whose LATEST
        # attestation is in that subtree
        head = max(
            children,
            key=lambda c: get_weight(c)
        )

def get_weight(block):
    # Sum effective_balance of validators
    # whose latest attestation targets a
    # descendant of block (or itself)
    weight = 0
    for v in active_validators:
        target = store.latest_messages[v].root
        if is_ancestor(block, target):
            weight += v.effective_balance
    return weight

🔑 Key Properties

L — Latest Message Driven
Only each validator's most recent attestation counts. Old votes are discarded.
M — Message
An attestation = message with beacon_block_root (head vote) + source→target (FFG vote).
D — Driven
Fork choice is entirely driven by attestations. No longest-chain rule.
GHOST — Greedy Heaviest Observed SubTree
At each fork, choose the branch with the most total attestation weight in its entire subtree. Greedy = decide at each level, no backtracking.

⚡ Why Not Longest Chain?

Bitcoin: longest chain (most PoW). Slow — need 6+ confirmations (~60 min).

Ethereum: heaviest subtree (most attestation weight) + Casper FFG = economic finality in ~13 min.

🏛️ Casper FFG

Finality Gadget

• Determines justified & finalized checkpoints

• Uses source→target supermajority links

• Checkpoints at epoch boundaries

• Evaluates every epoch (~6.4 min)

• Provides safety — finalized = irreversible

🔗 How They Interact — Per-Slot Process

🗳️ Supermajority Link

A supermajority link S→T exists when ≥2/3 of validators attest:

source = S (justified checkpoint)
target = T (epoch boundary block)
votes(S→T) ≥ ⅔ × total_active_balance

When S→T is a supermajority link:

• T becomes justified

• If T.epoch == S.epoch + 1 → S becomes finalized

⚖️ Proposer Boost

Proposer weight boosting gives the current slot's proposed block a temporary weight bonus to prevent reorg attacks.

proposer_boost = committee_weight × 40/100

// Applied to the block proposed for the
// current slot, only during that slot

Prevents ex-ante reorgs where an adversary withholds their block to reorg a competing one.

Attack Scenarios & Defenses

How the fork choice handles adversarial behavior

ATTACK

Balancing Attack

How it works: Attacker controls a small fraction of validators. They strategically release attestations to keep two branches at roughly equal weight → delays finality.

Impact: Honest validators split. No 2/3 majority forms.

Defense — Proposer Boosting: Newly proposed block gets a temporary weight bonus (40% of committee weight), making it harder to balance the fork.

ATTACK

Ex-Ante Reorg (Block Withholding)

How it works: Proposer P₁ at slot N withholds their block. Honest proposer P₂ at slot N+1 builds on N-1. P₁ releases late with accumulated attestations → reorgs P₂.

Goal: Steal P₂'s MEV or censor transactions.

Defense — Proposer Boosting: P₂'s block gets immediate weight boost so late blocks can't reorg it.

ATTACK

Long-Range Attack

How it works: Old validators who withdrew create a fake alternate chain from the distant past using their old keys.

Defense — Weak Subjectivity: New nodes sync from a recent weak subjectivity checkpoint (≤ ~2 weeks old). Chains diverging before this are ignored.
